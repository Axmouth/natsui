THE REAL THING, LOCALLY

One command. A cluster in motion.

Three NATS servers, Natsui and a traffic generator. Producers burst, consumers fall behind, retries happen and backlogs drain. All records and metrics come from real broker activity.

Docker Compose 2.34+ / Linux containers
docker compose -f oci://ghcr.io/axmouth/natsui-demo:latest up -d --wait

Then open 127.0.0.1:4321. The same command works in PowerShell, Bash and Zsh. AMD64 and ARM64 images are published.

The first run downloads images. Port 4321 must be available. Docker may ask to confirm the bundle's configuration. Only the dashboard port is published, on loopback. No host directory or Docker socket is mounted.

3 brokersUnmodified NATS servers with real JetStream replication.
5 consumersIndependent workers, a shared work queue and delayed retries.
120-second cycleSteady traffic, slow consumption, a burst and recovery.
Local historySQLite records observations and reviewed configuration changes.
Stop, restart, reset or choose another port

Stop the demo and retain its broker data and dashboard history:

docker compose -f oci://ghcr.io/axmouth/natsui-demo:latest down

The start command resumes it. Adding -v to the stop command also deletes this demo's named volumes and saved history.

For another dashboard port, set NATSUI_DEMO_PORT before running the start command:

# Bash / Zsh
export NATSUI_DEMO_PORT=4322
# PowerShell
$env:NATSUI_DEMO_PORT='4322'

The demo is an isolated, unauthenticated local environment. Reviewed JetStream edits are enabled for this demo; standalone Natsui connections are read-only by default.

Download the Compose file instead

Download natsui-demo.yaml, then run:

docker compose -f natsui-demo.yaml up -d --wait

This file contains the full cluster definition, with no local build or supporting files. Docker Compose 2.23.1+ is required for inline configuration.
